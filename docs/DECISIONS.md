# Decisions and open questions

Record each decision with date, reason and the doc line relied on.

## Decisions

| Date | Decision | Reason |
| --- | --- | --- |
| 2026-11-05 | All payment code goes through one `agent-account` interface with two implementations (Agent API, fallback vault) | Agent API access/quotas are uncertain; features must not depend on which one is used |
| 2026-11-05 | Owner approves the weekly plan as a whole; single approvals only above a threshold or for new payees | Human approves the plan, not every click |
| 2026-11-05 | Payout address changes are owner-only with a 48h hold flag | Most common invoice fraud |
| 2026-11-05 | Prisma + SQLite by default; dry-run is the default mode | Judges can run it with no keys or services |
| 2026-11-05 | No naira bank payouts | Needs licensed partners; out of scope |
| 2026-11-05 | **Agent account = NEAR Intents Agent API** (`@near-intents-agent-api/sdk` 0.7.3). The fallback vault is **not built** unless the human declines mainnet use or cannot get a key. `agent-account.ts` keeps two implementations: `agent-api` (live) and `simulated` (dry-run, evaluates the same `Policy` type locally) | The policy covers every rule PRD §5.1 needs and pays cross-chain natively; a testnet vault could not pay cross-chain at all because Intents has no testnet. See A1–A6 below |
| 2026-11-05 | **Payment route:** payees on another chain are paid by the agent with `swap` (inside its Intents balance, if the token differs) then `withdraw` to the payee's allowlisted address; payees on NEAR Intents by `transfer`. We do **not** pay to 1Click deposit addresses from the agent account | A fresh 1Click deposit address per quote cannot be on the owner's allowlist, so the allowlist would be meaningless. `withdraw` destinations are checked against the owner's `destinations: only` list (A3) |
| 2026-11-05 | Plan cost estimates use 1Click **dry** quotes with `depositType: INTENTS` (no key needed) | Live: NEAR-USDC quotes with `depositType: ORIGIN_CHAIN` were refused ("Quoting for this pair is not available"); `INTENTS` quotes at $5 and $50 to Tron and Base returned 201 (B3) |
| 2026-11-05 | Reader model: `Qwen/Qwen3-VL-30B-A3B-Instruct` on NEAR AI Cloud; PDFs are rasterised or text-extracted before sending | Reads images, structured outputs, NEAR-owned TEE model with attestation (C1–C2) |
| 2026-11-05 | Dry-run payees use hash-derived, checksum-valid addresses nobody holds keys for (`lib/demo-addresses.ts`) | 1Click validates the recipient even on dry quotes; the docs' Tron example address fails the checksum (B3) |
| 2026-11-05 | Duplicate-payment protection stays in the app (duplicate check + idempotency keys) | The Agent API policy cannot stop a second payment to an allowed payee (A6) |
| 2026-11-05 | Dry-run duplicate check = same supplier + same invoice number, or same supplier + same total within 14 days (not "same amount from anyone") | Avoids holding normal repeat orders from different suppliers; recurring staff pay is exempt |
| 2026-11-05 | Pinned Prisma 7.10.1 (npm `latest` tag is `8.0.0-rc.30`, a release candidate) | Stable over RC for a judged demo |

## Answers to the M0 open questions (checked 5 Nov 2026)

### A. Agent API (`docs.agentsonintents.com`, repo `NEAR-Intents-Agent-API/sdk-typescript`)

- **A1 Access and network.** Both the demo and production APIs run on **mainnet**. `GET https://api.demo.agentsonintents.com/v1/network` → `"network":"mainnet","contract_id":"outlayer.near"`. Docs (quickstart/introduction): "There is no testnet version of NEAR Intents or the Agent API. Everything here runs on mainnet with real funds." Demo keys: self-service "Create Demo Developer Account" on https://partners.demo.agentsonintents.com/dashboard; production keys: "Key: starts with naa_, created in the Partner Dashboard, shown once, never expires" (…/authentication). Key rotation of demo keys: **not documented** (only in the hackathon brief).
- **A2 Quota.** "Agents created per rolling 24 hours, across all keys 100 … A failed or deleted agent does not refund its slot" (…/network-and-quotas). "1,000 custody operations per rolling 24 h" (SDK README).
- **A3 Policy covers PRD §5.1.** Policy type (SDK `src/generated/api.d.ts`): `frozen, actions, confidential, owner_approval, assets, limits{per_transaction,hourly,daily,monthly}, max_actions_per_hour, destinations{mode:"only"|"except"|"any", list}, budget{daily_usd,weekly_usd,monthly_usd}, timelock_ms, schedule`. Weekly cap → `budget.weekly_usd` (fixed periods: "up to twice a cap can move across a reset"). Per-payment cap → `limits.per_transaction` (per asset, atomic units). Allowlist → `destinations: {mode:"only", list:[{action:"withdraw", chain, address, memo}, {action:"transfer", address, confidential}]}`; "`only` matches the **exact** entry, memo included"; "EVM addresses … must be lowercase hex." Freeze → `agent_freeze`/`agent_unfreeze` owner intents, "agent_freeze is never throttled." Only the owner changes it: "Only the owner's signature can change the agent's rules" (…/concepts).
- **A4 Cross-chain from the agent account.** "Public and confidential withdrawals reach every `blockchain` value `GET /v1/tokens` lists (`near`, `eth`, `sol`, `btc`, `tron`, …)." `withdraw(agentId, {asset, amount, chain, recipient, memo?, confidential?, dry?})`; `transfer(agentId, {asset, amount, recipient, confidential?})`.
- **A5 Who refuses.** "The API enforces destinations, budget, timelock_ms and schedule itself. The wallet provider enforces the rest (actions, assets, limits, max_actions_per_hour, owner approval and freeze)" (…/policies-and-limits). The API runs in "an attested Intel TDX confidential VM"; the wallet layer is "a TEE-backed signer" whose rules are "written to the NEAR blockchain" (…/concepts). Refusal codes: `policy_destination_denied`, `spend_budget_exceeded`, `policy_transaction_limit_exceeded`, `wallet_frozen`, … "no operation exists, nothing is charged." A dry preview "never refuses … it warns: `quote.warnings[].code`". **README must say:** the allowlist and weekly budget are enforced by the Agent API service in a TEE, the per-payment cap and freeze by the TEE wallet provider — not by Bursar's code or the AI.
- **A6 Limits we must cover ourselves.** Policy changes have a cooldown (docs say both "10-minute cooldown" and "5 minutes by default" — **docs disagree**); batch payee additions into one owner signature. An allowed payee can be paid twice (open issue NEAR-Intents-Agent-API/examples#21) → app duplicate check. `native*` methods bypass the policy ("destinations, budget, timelock_ms, schedule and owner_approval don't apply") → Bursar never grants `native`. "Only one money action runs per agent wallet at a time" (`wallet_busy`) → pay sequentially.
- **A7 Owner signing.** Owner actions are `generateIntent` → owner signs (`nep413` message or `nep366` delegate action; "The SDK contains no signers") → `submitIntent`. NEAR owner key: docs say "public_key must be an ed25519 full-access key … function-call key is refused with owner_key_not_full_access (403)"; the examples README says "FullAccess not required" — **docs disagree; docs win.** The agent only ever holds a grant token (`ngt_…`), never the owner's key.
- **A8 Proofs.** `getOperationProof` + `verifyOperationProof(proof, origin)` check the transparency-log inclusion; "The TDX quote is not checked here" (SDK README). A proof "does not replace the execution's status."
- **Consequence:** creating the agent and signing its policy are **mainnet actions** → need the human's explicit OK (AGENTS.md rule 2). A refused payment costs nothing, so the M1 "rejected by the account itself" test can run against an unfunded agent.

### B. 1Click (`docs.near-intents.org`, OpenAPI `https://1click.chaindefuser.com/docs/v0/openapi.yaml`)

- **B1 Endpoints.** `GET /v0/tokens`, `POST /v0/quote`, `POST /v0/deposit/submit` (`txHash`, `depositAddress`, `nearSenderAccount?`, `memo?`), `GET /v0/status?depositAddress=…&depositMemo=…`. Auth: OpenAPI "`X-API-Key` … API key for partner authentication (recommended)"; Bearer is "legacy". (`docs/NEAR-NOTES.md` was right; the near-intents skill still shows Bearer.)
- **B2 Asset IDs** (live `GET /v0/tokens`, all 6 decimals): USDC on NEAR `nep141:17208628f84f5d6ad33f0da3bbbeb27ffcb398eac501a31bd6ad2011e36133a1`; USDT on Tron `nep141:tron-d28a265909efecdcee7c5028585214ea0b96f015.omft.near`; USDC on Base `nep141:base-0x833589fcd6edb6e08f4c7c32d4f71b54bda02913.omft.near`; USDT on NEAR `nep141:usdt.tether-token.near`; USDC on Solana `nep141:sol-5ce3bf3a31af18be40ba30f721101b4341690186.omft.near`; USDC on Arbitrum `nep141:arb-0xaf88d065e77c8cc2239327c5edb3a432268e5831.omft.near`. Code always looks them up from `/v0/tokens` at runtime.
- **B3 Required quote fields** (OpenAPI `required`): `dry, swapType, slippageTolerance, originAsset, depositType, destinationAsset, amount, refundTo, refundType, recipient, recipientType, deadline`. The recipient is validated even when `dry: true`. Dry responses carry `amountIn, minAmountIn, amountOut, timeEstimate, withdrawFee, refundFee` and a `signature`, but "will **NOT** contain … `depositAddress`, `timeWhenInactive`, `deadline`". Live dry quotes, USDC (Intents) → exactly 50 out: Tron USDT in 51.35 USDC (withdraw fee ≈ $0.87); Base USDC in 50.52 USDC.
- **B4 Minimums.** 9 Sep: "We're temporarily blocking origin → origin swaps under \$1,000 USD on these chains… This does not affect deposits to or withdrawals from Intents" (BSC, Polygon, TON, Optimism, Avalanche, Stellar, Monad, XLayer, ADI). 14 Sep: under \$100 "when the deposit token is on Tron". Neither lifted as of today. Quotes from an Intents balance at $5 and $50 had no minimum error → Bursar's route is unaffected.
- **B5 Fees** (…/resources/fees.md): "**Without API key** | Additional **0.25% (25 bps)** on every non-`ANY_INPUT` quote"; "**With API key, no `appFees`** | **0.20%** … **0.01% (1 bp)** for stablecoin pairs"; with `appFees` "Split 50/50, with 1Click keeping at least **20 bps** (or **1 bp** on stablecoin …)". Fee config: combined total "cannot exceed **500 bps**". **Observed mismatch:** with no key the live API echoed a 1 bp fee (not 25) and split a 50 bps `appFees` 25/25. We plan with the documented 25 bps. HACKATHON.md Q-006 says "0.2%" — docs win.
- **B6 Confidential settlement** (changelog 2026-10-27): "1Click swaps settle confidentially. The API is unchanged… `nearTxHashes` has no hash for the swap. It has the hashes for the shield and the unshield instead." `/v0/status` still returns `correlationId`, `quoteResponse.quote.depositAddress`, `status`, and `swapDetails.destinationChainTxHashes[{hash, explorerUrl}]` → the statement can link the payee-side transaction. There is no separate quote ID; the deposit address is the key. The `confidentiality` request parameter needs auth ("User authentication is required for confidential intent quotes").
- **B7 No testnet.** FAQ: "There is no testnet deployment and no plans for one."

### C. NEAR AI Cloud (`docs.near.ai`)

- **C1 API.** Base URL `https://cloud-api.near.ai/v1`, "Authorization: Bearer sk-<api_key>". `GET /v1/models` is public and lists `input_modalities` and `supported_features`.
- **C2 Model.** `Qwen/Qwen3-VL-30B-A3B-Instruct`: "accepts images in standard OpenAI chat format (`image_url` content parts) on `/v1/chat/completions`" (…/guides/specialized-endpoints); `/v1/model/…` → `"verifiable":true, "attestationSupported":true, "supportedFeatures":["structured_outputs","logprobs"]`. Fallback `z-ai/glm-5.3-flash`. PDFs: `/v1/files` is retired ("no longer available"), so we rasterise or extract text first. Base64 `data:` URLs are not explicitly documented — verified by `npm run smoke:nearai` once a key exists.
- **C3 Privacy tiers.** "**Confidential TEE** … run on NEAR AI's own GPU fleet inside Trusted Execution Environments"; "**Incognito** models … run on the provider's infrastructure, outside a TEE." Only `ownedBy: nearai` models are TEE end to end; ours is one.
- **C4 Attestation (P1, B12).** `GET /v1/attestation/report?model=…&provider=near&signing_algo=ecdsa&nonce=<64 hex>` with `x-no-aliasing: true`; verify gateway then each `model_attestations[]`; Intel quote via `dcap-qvl`; report data = signing address ‖ nonce; replay event log to RTMR3; MRCONFIGID = `01` ‖ sha256(app_compose) ‖ zeros; GPU evidence to NVIDIA NRAS; then `GET /v1/signature/<chat_id>?signing_algo=ecdsa` and recover the EIP-191 signer (…/verification/cloud-api/model-attestations).
- **C5 Credits.** Quickstart: sign up at cloud.near.ai → buy credits → generate key. **The $10 builder credit is not in the docs** — human to confirm via nearbuilders.org/join.
- **Skill vs docs:** the near-ai-cloud skill's model table and verification steps are out of date; live docs win.
